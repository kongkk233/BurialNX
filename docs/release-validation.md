# Release validation

`npm run verify:release` first runs the executable profile validator, the repository-verifiable runtime provenance gate, generic structural `accept:package` plus generic script-executing `accept:package:runtime` against a synthetic profile-driven fixture, the neutral `port:check`, base `accept:host`, mod-overlay `accept:overlay`, and the explicit neutral smoke contract; it then runs host tests, the controlled TypeScript module/bundle check, the desktop Chromium media probe (writing the ignored commit-bound `browser-validation.json`), asserts a clean worktree, performs two host NRO builds and compares their byte hashes, checks the NRO structural header, and writes `release-manifest.json`. The manifest records package version, git commit, whether the worktree was dirty, a deterministic source-tree SHA-256, Node/npm versions, lockfile SHA-256, recomputed patch/preroll provenance, commit-bound browser MP4/WebM evidence, the release/debug NRO artifact set when present, per-artifact SHA-256/executable digest/NACP identity and policy, runtime executable digest (or an explicit null), NACP source summary, generic package acceptance including the synthetic production sleep/wake lifecycle control-flow probe and Node/NW fs shim contract probe, neutral host acceptance checks and evidence, mod-overlay host acceptance checks and evidence, the neutral smoke report, and the two-build reproducibility report. The verifier cross-checks overlay precedence, smoke checks/evidence against fresh host acceptance, runtime file claims and browser results against the current checkout, and binds all reports to the current clean commit and complete artifact set. Dirty worktrees, commit-mismatched smoke/repro/provenance/browser reports, stale artifact hashes/NACP identity, and non-identical host builds are release-gate failures; generate the final artifact from the clean `main` commit.

Validation levels:

- **Package contract acceptance**: `npm run accept:package` checks a profile, entry, ordered script graph, safe asset paths, media policy shape, dynamic save naming, and session rollback without executing game scripts. It also reports `entryScript.graph` for a declared `entry.script` while keeping `entryScript.execution.status: not-observed`, exercises the session timer cleanup registry, and reports matching timeout/interval cancellation attempts with zero cleanup failures. Its `evidence.lifecycle` is a synthetic production control-flow probe: `handleWake(true)` saves, writes the marker, calls production `teardownGame()` and launches the same NRO; the report requires matching timer cleanup and zero cleanup failures. Its `evidence.nodeCompat` is a separate host-shim contract probe: app-root escapes are rejected with `EPERM`, writes and replacements stay overlay-only, packaged-file rename is rejected, and missing native rename fails with `ENOSYS`; both explicitly remain host evidence, not Switch hardware or external-runtime evidence. It uses only the synthetic `tests/fixtures/generic-mv` fixture and reports `executedGameScripts: false` / `runtimeBehavior: not-observed`.
- **Package runtime acceptance**: `npm run accept:package:runtime` executes the same game-neutral fixture's ordered scripts in the host VM, starts the production `runtime-plan` fallback, and reports `executedGameScripts: true` / `runtimeBehavior: observed`. Its `declaredRuntime` is copied from `profile.runtime`; its separate `actualExecution` records `mode: host-runtime`, `engine: vm-host-fixture`, and the Node host version with `status: observed`. For a declared `entry.script`, `entryScript.execution` is `observed` only when the exact graph path executes at the same index; this is still host-VM evidence, not automatic injection or external-engine proof. `actualExecution.externalRuntime.status` remains `not-verified`: the fixture does not launch or verify an external NW.js/runtime, even when the profile declares `runtime.kind: nwjs`. It does not require the neutral fixture marker and is still not evidence for an arbitrary commercial game or Switch hardware.
- **Optional external runtime identity**: `npm run accept:external-runtime -- --runtime <nwjs> --game-root <www>` launches the explicitly supplied desktop executable with an isolated probe app. The probe binds a random nonce, the requested executable's SHA-256, observed `process.versions.nw`, `process.execPath`, and a host-side package/profile binding; it deliberately does not load the original game root or execute game scripts. The report labels that package binding as `bindingSource: host-port-check` and `probeBinding: host-provided-echo`, so a pass is `scope: external-runtime-identity` only and is not package compatibility evidence. Without `--runtime` the report is `status: not-verified`; no runtime is downloaded and the default release gate remains unchanged. A pass is not Switch nx.js, native source rebuild, hardware, or commercial-game evidence. Version matching is exact unless the profile explicitly uses `x` or `*` wildcards; partial versions such as `0.29` fail closed. To bind a real pass into a release manifest, write the report outside the checkout and run `BURIALNX_EXTERNAL_RUNTIME_REPORT=/path/to/report.json npm run verify:release`; the manifest records `externalRuntime.status: pass`, `validation.externalRuntime: external-runtime-identity: pass`, and the report path. With no environment variable, the manifest records the explicit `externalRuntime.status: not-run` boundary and the default gate is unchanged. Supplied reports must use `execution: external-process-probe`; injected test reports are rejected by the release verifier.
- **Port contract**: `npm run profile:validate` and `npm run port:check`; this is structural and profile-driven. The checker labels `entry.html`, the ordered script graph, path safety, media policy, save contract, and compatibility flags as `enforced`; `entry.script` as `validated-only`; runtime kind/version and package declarations as `metadata-only` unless the profile explicitly declares `package.manifest`, in which case `port:check` verifies that JSON manifest's name/version against the profile; and target runtime/native/hardware behavior as `not-observed`. The `compat.mv`, `compat.node`, and `compat.nwjs` flags are applied by `game-launch` before game startup.
- **Neutral deep acceptance**: `npm run accept:host`, `npm run accept:overlay`, and `npm run smoke:neutral`; these intentionally exercise the repository's neutral fixture and remain separate from generic package acceptance.
- **Host**: `npm test`; no real game directory and no hardware.
- **Runtime provenance**: `npm run verify:runtime-provenance` recomputes tracked patch and preroll-runtime gzip hashes, the decompressed NRO program digest/size, the NRO `ModuleId`/ELF BuildID, and the historical distributed Git blob identity. Historical package hashes are recorded as external `not-verified` evidence, because package identity does not prove the original source-build process. The report marks external nx.js source, SDK/toolchain, signing, and standalone-artifact claims as `not-verified`; this is not a complete native source rebuild.
- **Build/typecheck**: reproducible dependency install with `npm ci`, NRO packaging, and production graph resolution. The manual GitHub release workflow uses pinned action commits and refuses to build unless the requested version tag resolves to the checked-out commit.
- **Smoke**: `npm run smoke:neutral` checks the repository fixture through the explicit `neutral-port-contract` mode; a permitted full MV directory uses `BURIALNX_GAME_ROOT=<www> npm run smoke` and the development-only simulated-frame harness. The release manifest does not infer full-game smoke or hardware results.
- **Browser**: `npm run test:movie:browser -- --report browser-validation.json` is required by `npm run verify:release` and runs as a separate CI job with Chromium. It samples real decoded pixels/PCM for the synthetic MP4/WebM fixtures and binds the report to the clean checkout commit; `release-manifest.json` records the result. CI uploads this report and the release job downloads and validates the exact artifact with `BURIALNX_REUSE_BROWSER_REPORT=1` instead of silently replacing it. This is desktop-browser evidence only, not native Switch, hardware, or commercial-game evidence.
- **Release artifact provenance**: the manual Build NRO workflow and the CI release job build `burialnx.nro` and `burialnx-debug.nro` from the checked-out commit before running the clean release gate with `BURIALNX_REQUIRE_DEBUG_ARTIFACT=1`. The schema-4 manifest binds both NROs when the debug file is present: each record carries the file hash, size, executable-section hash, role, NACP title/author/application ID, and the fixed startup/save/journal/BCAT policy. Local `verify:release` remains compatible with a release-only checkout unless that environment variable is explicitly enabled. This is host/package artifact evidence only; it does not prove Switch acceptance, runtime execution, hardware behavior, native source provenance, or commercial-game compatibility.
- **Native source rebuild**: `node tools/rebuild-preroll-runtime.mjs <clean-nxjs-source> <new-build-dir>` is a separate fail-closed provenance check. It validates the pinned source/patch inputs, writes `native-rebuild-report.json` in the new build directory after linking, and refuses to replace `runtime/nxjs-preroll.nro-code.gz` when the linked executable digest differs. The distributed blob's historical Git lineage is recorded in `runtime/manifest.json` and verified locally by its Git blob identity, but its historical ARM Mac build claim remains unverified. The report must carry the 40-character release project commit (`BURIALNX_PROJECT_COMMIT` is supplied by CI when the pinned container has no `git`); the release verifier rejects an attempted pass/mismatch report without that binding. The pinned amd64 facts and the expected mismatch are recorded in [native-rebuild.md](native-rebuild.md); when that report is supplied, the release records `native: not verified (executable digest mismatch)` until the exact source-to-distributed-runtime relation is independently reproduced. A missing report is explicitly `schema: 1`, `status: not-run` and is not native evidence.
- **Native**: optional `npm run test:movie:native`; requires native fixtures/toolchain and an external patched nx.js source tree. A host/native probe is not the same evidence as a source rebuild or physical device run.
- **Hardware**: physical Switch playback and operator evidence. It is not inferred from a passing host test or NRO build, and the manifest remains `not verified` unless explicitly observed.

A release package must include the generated release NRO and manifest; the manual artifact set also includes the debug NRO, which is bound by the same host-side attestation. NACP metadata comes from the package manifest used by the build; it is not a claim that a target game was tested.
