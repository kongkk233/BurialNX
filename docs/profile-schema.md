# Port Profile schema

A Port Profile is versioned JSON describing the minimum contract between the loader and an RPG Maker MV/NW.js package. The canonical JSON Schema is [`../profiles/schema.json`](../profiles/schema.json). `npm run profile:validate -- <profile.json>` applies that schema with Ajv and then runs the production `parsePortProfile` parser, so the declarative schema and runtime normalization are both exercised; TypeScript callers should use `parsePortProfile` for strict validation and normalized defaults.

Required sections are `runtime`, `entry`, `compat`, `save`, and `package`; `assets` and `media` are optional and receive safe defaults. `assets.hashedLookup` controls the profile's short hashed-name fallback. `assets.envelope` is an explicit, versioned in-memory decoder contract (`basename-xor-v1`) and must only be used when the package owner can document that format. Version `1` defaults media extension fallback to MP4/WebM siblings and variant fallback to `-l`. Profiles are game-neutral: do not encode title IDs, private SD paths, or redistributed game content.

`entry.html` is the active launcher input: the loader reads it and follows its ordered local `<script src>` tags. If `entry.script` is present, it is an active validation contract: it must appear in that ordered script graph; it is not injected or reordered. `assets` and `media` drive asset and media resolution. `compat.mv` controls MV compatibility patches/language hooks and script preparation; `compat.node` and `compat.nwjs` independently control the Node.js and NW.js shim globals installed before game scripts execute. `save.extension` drives the file-based MV slot/config/global filename suffix, discovery, journaling, backups, recovery, and Steam import targets; it does not alter Switch-user `localStorage` keys, which retain MV's `RPG Config`/`RPG Global`/`RPG File<n>` namespace. `save.directory` describes the package-relative save directory contract and is recorded in launch diagnostics, while the actual writable destination remains the user's explicitly selected and safety-checked folder. `runtime.kind`, `runtime.version`, and `package` remain validated declarations in v1: `port:check` emits them, but the loader does not claim to discover or enforce an external NW.js/browser version or package-manager identity.

Unknown future fields should be rejected by the current schema until a profile version explicitly defines them. The phase-one launcher does not require a profile, so existing installations remain compatible.
